# 志賀町めぐり・お宝ガチャ図鑑

石川県志賀町の観光促進アプリです。
現地に掲示されたQRコードを読み取ってコインを集め、ガチャを回してカード全50種を集めます。

**テーマ**: 石川の日本酒を最高に味わうための「アテ・スポット・酒器」を志賀町で集める。

---

## ⚠ 公開前に必ずやること

### 1. カードの記載内容を確認する

カード50種の名称・産地・由来などは、**まだ公式情報と照合していません**。
`docs/card-facts.md` に確認用のチェックリストがあります。

確認できたカードは `src/data/cards.ts` の `verified` を `true` に変えてください。
誤った観光情報は来訪者の不利益に直結します。**未確認のまま公開しないでください。**

### 2. 営業状況の注記を確認する

2024年1月の能登半島地震の影響で、休業中・通行止めの場所があります。
アプリには常時その旨の注記と公式サイトへのリンクを表示していますが、
リンク先（`src/data/genres.ts` の `OFFICIAL_TOWN_URL`）が正しいか確認してください。

### 3. ライセンスを確認する

`docs/licenses.md` を参照してください。公開物にコピーレフト系のコードは含まれていません。

## 動かしてみる

```bash
npm install
npm run dev
```

→ http://localhost:3000

最初から10コイン持っているので、すぐに10連ガチャを試せます。

### QRコードの動作を試す

現地に行かなくても、次のどちらかで試せます。

- ホーム画面の「QRを読み取る（デモ）」ボタンを押す
- ブラウザで `http://localhost:3000/?spot=ganmon` を直接開く

### 最初からやり直す

ブラウザの開発者ツール → Application → Local Storage から
`shika-meguri-v1` を削除してリロードしてください。

## コマンド一覧

| コマンド | 何をするか |
|---------|-----------|
| `npm run dev` | 開発用サーバーを起動する |
| `npm run build` | 静的サイトを `out/` に書き出す |
| `npm test` | 抽選ロジックのテスト（排出確率が均等かを10万回引いて検証） |
| `npm run gen:docs` | カードデータから確認用ドキュメントを生成する |
| `npm run build:pages` | **本番と同じサブパス付き**でビルドする |
| `npm run preview:pages` | 上に加えて、本番と同じURL構造でローカル配信する |

### `preview:pages` が特に重要な理由

GitHub Pages では URL が `https://ユーザー名.github.io/shika-meguri/` のように
リポジトリ名ぶんの階層を挟みます。この階層を考慮し忘れると、
**ローカルでは動くのに本番だけ画像もCSSも読めない**という事故が起きます。

`npm run preview:pages` はその階層を再現して配信するので、
公開前にここで画面が崩れていないことを確認してください。
読み込みに失敗したファイルはターミナルに `404` として表示されます。

## GitHub Pages に公開する

1. このフォルダを GitHub のリポジトリに push する（ブランチは `main`）

   ```bash
   git init
   git add .
   git commit -m "志賀町めぐり・お宝ガチャ図鑑"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/shika-meguri.git
   git push -u origin main
   ```

2. リポジトリの **Settings → Pages → Build and deployment → Source** を
   **「GitHub Actions」** に変更する
3. 以降、`main` に push するたびに自動で公開されます

公開URLは `https://<ユーザー名>.github.io/<リポジトリ名>/` です。
リポジトリ名は `.github/workflows/deploy.yml` が自動で読み取るため、
リポジトリ名を変えても設定を書き換える必要はありません。

## カードの写真を追加する

`public/cards/` に、決められたファイル名で画像を置くだけです。
ファイル名の一覧は `public/cards/README.md` にあります。

- 形式: JPEG または PNG
- サイズ: 正方形 800 × 800 ピクセル程度
- 容量: 1枚あたり 200KB 以下が目安

**画像が無いカードは、ジャンル色のプレースホルダーが自動表示されます。**
写真を1枚も用意しなくてもアプリは完成した状態で動きます。

## 現地に掲示するQRコードを作る

`docs/qr-list.md` に、全20スポットぶんのURL一覧があります。
`<公開URL>` を実際の公開先に置き換えてQRコードにしてください。

例: `https://ユーザー名.github.io/shika-meguri/?spot=ganmon`

### コインの付与ルール

| 状況 | 獲得コイン |
|------|-----------|
| 初めて読み取ったスポット | 3枚 |
| 同じスポットの再読み取り（24時間以上あけて） | 1枚 |
| 24時間以内の再読み取り | 0枚（次回可能時刻を表示） |

## ガチャの仕様

- **レア度なし。** 全50種すべてが均等な確率（各2%）で出ます
- シングル = コイン1枚 / 10連 = コイン10枚
- すでに持っているカードが出たら、1枚につきコインが1枚戻ります
  （コイン切れで遊べなくなるのを防ぐため）
- 全50種を集めると、デジタル認定証が解放されます

## 技術的な注意点

### アセットのパスは必ず `asset()` を通す

`public/` の中のファイルを参照するときは、必ず `src/lib/asset.ts` の
`asset()` を通してください。直接 `/cards/x.jpg` と書くと本番で404になります。

### 3D部分はブラウザ専用

`ChestScene.tsx` は `next/dynamic` の `ssr: false` 経由でのみ読み込んでいます。
ビルド時にはWebGLが存在しないため、直接importするとビルドが失敗します。

### `useSearchParams` は Suspense で囲む

静的書き出しの制約です。`ScanPanel.tsx` の `SpotParamReader` が実例です。

### Windows でビルドすると出る警告について

Windows 上で `npm run build` すると、画面遷移を速くするための小さなデータファイルの
名前が正しく作られない不具合が Next.js 16.3.1 にあります
（`__next.gacha.__PAGE__.txt` が `__next.gacha/__PAGE__.txt` になる）。

**GitHub Actions は Linux で動くため、公開後の動作には影響しません。**
`npm run preview:pages` はローカル確認のためにこれを自動で補正します。

## 対応環境

- スマートフォンでの利用を主に想定（画面下部のタブで操作）
- 3D表示に対応していない端末では、CSSのみの簡易演出に自動で切り替わります
- OSの「視差効果を減らす」設定が有効な場合、演出を短縮します
- 演出はいつでも「演出をスキップ」ボタンで飛ばせます

## データの保存について

所持コイン・カード・訪問履歴は、すべて**利用者の端末の中だけ**に保存されます
（LocalStorage）。サーバーには一切送信されません。
